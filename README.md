# Определение перевернутого текста (0 / 180)

Тестовое задание: по картинке бокса с текстом предсказать `p_180`, вероятность того что текст перевернут вверх ногами.
Метрика 1 - Brier score.

**Коротко:** маленькая сверточная сеть (273к параметров, 1 МБ в onnx, около 1 мс на бокс на одном ядре cpu),
обученная на синтетике с кириллицей и реальных фотках текста из открытых OCR датасетов.
На валидации 1 - Brier = 0.972 на синтетике и 0.902 на реальных фотках.

Все решение (данные, синтетика, модель, обучение, экспорт, предикт) лежит еще и в одном ноутбуке `solution.ipynb`.
Открыть его из корня репозитория и запустить все ячейки, в конце получится `submission.csv`.
Флаг `TRAIN` в первой ячейке: `False` (по умолчанию) берет готовые веса из `weights/`, `True` делает все с нуля
(часа два на cpu). Код там тот же что в `src/` и `scripts/`, просто собран в одном месте.

### Все с нуля

```bash
# данные для обучения (скачиваются сами)
python scripts/download_fonts.py         # шрифты с кириллицей из google fonts
python scripts/build_text_corpus.py      # тексты из датасета товаров ozon

python -m src.train --name base_w1

Для сравнения еще учил сеть в 2 раза уже: `python -m src.train --name w05 --width_mult 0.5`.
Сиды везде зафиксированы. Все делал на cpu (4 ядра), видеокарты нет.

## Подход

### Идея

Обучающих данных нет, но для этой задачи они и не нужны: любая картинка с текстом, которая стоит правильно,
после поворота на 180 становится примером класса 1. Значит нужно просто много правильно стоящих кропов текста,
похожих на тест, а метку делаем сами случайным поворотом прямо во время обучения.

### Что в тесте (notebooks/01_eda.ipynb)

Реальные кропы с фоток объявлений: вывески, упаковки, этикетки, скриншоты, номера машин, логотипы, иногда рукописный текст.
В основном русский, но латиницы тоже много. Треть картинок ниже 32 пикселей, много размытых. Вертикального текста почти нет.
На глаз перевернута примерно половина.

### Данные для обучения (примеры в notebooks/02_data_preview.ipynb)

1. **Синтетика, 300к картинок** (`src/synth.py`)
   * тексты из открытого датасета товаров ozon (названия, куски описаний, характеристики) + шаблоны:
     телефоны, цены, номера машин, адреса, сайты, фразы типа "Торг уместен"
   * 204 семейства шрифтов с кириллицей из google fonts, всего 536 файлов (обычные, жирные, курсив)
   * случайный фон, иногда обводка, тень, куски соседних строк, потом небольшой поворот,
     неточная обрезка бокса, уменьшение, блюр, шум, jpeg
   * поля вокруг текста сверху и снизу случайные с одинаковым распределением, чтобы сетка смотрела на буквы, а не на отступы
2. **Реальные кропы, 66к** (`scripts/prepare_real_crops.py`): COCO-Text, ICDAR 2015, TextOCR (слова с фоток, английский)
   + русский рукописный текст и номера машин. Выкинул вертикальные кропы.

В батче 30% реальных кропов, остальное синтетика.

### Препроцессинг (`src/common.py`, один и тот же для обучения и предикта)

Серая картинка, высота 32, ширина по пропорциям, нормировка по самой картинке, ставим по центру холста 32 x 256.
Если картинка шире, сжимаем по горизонтали (это примерно 20% теста).

### Модель (`src/models.py`)

TinyCNN: обычная сверточная сетка как в OCR (CRNN), только без рекуррентной части.
Несколько блоков conv-bn-relu, по высоте сжимаем с 32 до 1, в конце свертка на всю оставшуюся высоту,
потом среднее по ширине и линейный слой выдает 1 логит.
Обучение: BCE с label smoothing 0.02, AdamW, OneCycle, 10 эпох по 150к картинок.

### Валидация

Меток для теста нет, поэтому проверяю на том где метки известны:
* **synth_val**: 10к синтетики, где шрифты (27 семейств) и тексты не пересекаются с трейном
* **real val**: 25к реальных кропов из тестовых частей COCO-Text, ICDAR 2015, TextOCR + отложенные 20% русских рукописных и номеров
* поворот на валидации фиксированный (сид), так что цифры между запусками можно сравнивать
* лучшую эпоху выбираю по среднему из двух скоров

Минус: реальная валидация в основном из коротких английских слов, а в тесте больше русского и длинных строк.
По валидации видно что длинные строки сильно проще коротких, так что на тесте скор скорее всего не хуже чем на real val.

## Результаты

1 - Brier на валидации, скорость: onnxruntime, одно ядро cpu (`src/export.py`).

| | synth_val | real val | параметров | размер | мс / бокс |
|---|---|---|---|---|---|
| константа 0.5 | 0.750 | 0.750 | | | |
| TinyCNN w0.5 | 0.960 | 0.882 | 69к | 0.27 МБ | 0.4 |
| **TinyCNN w1.0 (финал)** | **0.972** | **0.902** | 273к | 1.07 МБ | 1.0 |

По источникам у финальной модели: COCO-Text 0.906, ICDAR 2015 0.924, TextOCR 0.892,
русский рукописный 0.967, номера машин 0.994.

Вероятности получились нормально откалиброванные и без отдельной калибровки (график в notebooks/03_results.ipynb).
Самое сложное для модели: короткие боксы из 1-3 символов и стилизованные логотипы.

## Что можно сделать дальше

* сеть пошире (переход с w0.5 на w1.0 дал заметный прирост, возможно дальше тоже будет)
* очень длинные строки не сжимать, а резать на куски и усреднять
* усреднять предсказание с повернутой картинкой (TTA)
* больше реальных русских кропов, в открытом доступе их почти нет

## Что использовал из open source

Библиотеки: PyTorch, onnxruntime, OpenCV, Pillow, numpy, pandas, fontTools, pyarrow, matplotlib.

Данные для обучения (все качается скриптами из `scripts/`):
* шрифты: [Google Fonts](https://fonts.google.com), только семейства с кириллицей, список в `scripts/fonts.txt` (лицензии OFL / Apache 2.0)
* тексты: датасет товаров ozon [evgmaslov/ozon_ecup](https://huggingface.co/datasets/evgmaslov/ozon_ecup), только текстовые колонки
* реальные кропы текста:
  * COCO-Text v2: [Bekhouche/COCO-Text_V2_STR](https://huggingface.co/datasets/Bekhouche/COCO-Text_V2_STR)
  * ICDAR 2015: [MiXaiLL76/ICDAR2015_OCR](https://huggingface.co/datasets/MiXaiLL76/ICDAR2015_OCR)
  * TextOCR: [MiXaiLL76/TextOCR_OCR](https://huggingface.co/datasets/MiXaiLL76/TextOCR_OCR)
  * русский рукописный текст и номера машин: [Foximaz/russian_ocr_small](https://huggingface.co/datasets/Foximaz/russian_ocr_small) (CC BY 4.0)

Архитектура по мотивам CRNN (Shi et al., 2015) и классификатора направления текста из PaddleOCR, только меньше.

```
